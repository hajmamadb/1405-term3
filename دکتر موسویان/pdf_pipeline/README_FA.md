# خط لولهٔ ترجمهٔ صفحه‌به‌صفحهٔ PDF (اسکرین‌شات + انگلیسی + فارسی)

ابزاری محلی که یک PDF انگلیسی را **صفحه‌به‌صفحه** پردازش می‌کند و برای هر صفحهٔ مبدأ
**سه صفحهٔ خروجی** می‌سازد:

| صفحهٔ خروجی | محتوا |
|---|---|
| **A** | اسکرین‌شات تصویری صفحهٔ اصلی (PNG، ذخیره‌شده روی دیسک) |
| **B** | متن انگلیسی استخراج‌شدهٔ همان صفحه |
| **C** | ترجمهٔ دقیق فارسی (راست‌به‌چپ، با فونت Vazir) |

هر صفحه **بلافاصله پس از اتمام ذخیره** می‌شود و در `state.json` ثبت می‌گردد؛
بنابراین اگر سرویس را ببندید و دوباره اجرا کنید، **صفحات انجام‌شده دوباره پردازش نمی‌شوند**.

---

## ۱) پیش‌نیازها

```bash
pip install PyMuPDF requests python-docx
```

اختیاری (برای خروجی PDF از Word):

```bash
sudo apt-get install -y libreoffice      # دستور soffice
```

فونت فارسی (برای نمایش درست در Word):

```bash
sudo apt-get install -y fonts-vazir      # یا فایل Vazir.ttf را در ~/.fonts بگذارید
fc-cache -f
```

---

## ۲) اجرای رابط هوشمند (پیشنهادی)

```bash
cd pdf_pipeline
python3 app.py                 # → http://127.0.0.1:8765
```

در مرورگر:

1. **آپلود PDF** یا انتخاب مسیر فایل از فهرست خودکار.
2. زدن «ℹ️ تعداد صفحات» برای دیدن تعداد و حجم.
3. وارد کردن **کلید API** (`sk-...`) — یا تیک «حالت آزمایشی» برای تست بدون API.
4. انتخاب مدل (`qwen38-nothinking` پیشنهادی)، بازهٔ صفحات و DPI.
5. **▶️ شروع پردازش** — لاگ زنده، درصد پیشرفت و دکمهٔ **⏹ توقف**.
6. از بخش «کارهای قبلی» می‌توانید **ادامه** دهید یا Word/PDF را **دانلود** کنید.

هیچ وابستگی وب‌فریمی ندارد: تمام رابط با `http.server` استاندارد پایتون ساخته شده است.

## ۳) اجرای خط فرمان

```bash
# ترجمهٔ واقعی کل فایل
python3 pdf_translate.py book.pdf --key sk-XXXX --make-pdf

# فقط صفحات ۱۰ تا ۲۰
python3 pdf_translate.py book.pdf --key sk-XXXX --start 10 --end 20

# تست ساختاری بدون تماس با API
python3 pdf_translate.py book.pdf --mock

# بازهٔ مشخص، کیفیت بالاتر
python3 pdf_translate.py book.pdf --key sk-XXXX --start 1 --end 5 --dpi 200

# بازسازی سند Word از حافظهٔ نهان (بدون ترجمهٔ دوباره)
python3 pdf_translate.py book.pdf --rebuild --make-pdf
```

### کلیدها و متغیرهای محیطی

| متغیر | پیش‌فرض |
|---|---|
| `ISMC_API_KEY` | (خالی — با `--key` بدهید) |
| `ISMC_BASE_URL` | `https://ai.ismc.ir/api/v1` |
| `ISMC_MODEL` | `qwen38-nothinking` |
| `PDFT_WORKDIR` | `./pdf_translate_out` |
| `PDFT_DPI` | `150` |

## ۴) ساختار خروجی

```
pdf_translate_out/
└── <نام فایل>/
    ├── state.json              # رکورد صفحات انجام‌شده (کلید = SHA1 فایل PDF)
    ├── screenshots/
    │   ├── page_0001.png       # اسکرین‌شات هر صفحه
    │   └── ...
    ├── texts/
    │   ├── page_0001.txt       # متن انگلیسی استخراج‌شده
    │   └── ...
    ├── <نام فایل>_fa.docx      # سند نهایی ۳صفحه‌ای برای هر صفحهٔ مبدأ
    └── <نام فایل>_fa.pdf       # اگر --make-pdf بدهید
```

`state.json` با **SHA1 فایل PDF** کلید می‌خورد؛ اگر PDF دیگری در همان پوشه باشد،
فایل وضعیت جداگانه (`state_<sha8>.json`) ساخته می‌شود.

## ۵) نکات فنی و محدودیت‌ها

* **جای‌گذاری سه‌صفحه‌ای**: از `page_break_before` روی پاراگراف سرصفحه استفاده می‌شود
  (نه پاراگراف خالی)، بنابراین هیچ صفحهٔ خالی‌ای در خروجی نمی‌افتد.
  برای هر صفحهٔ مبدأ دقیقاً سه صفحه تولید می‌شود.
* **صفحات اسکن‌شده**: اگر صفحه فقط تصویر باشد، متن قابل استخراج نیست؛ در آن صورت
  صفحهٔ A تصویر را نشان می‌دهد و در صفحهٔ B/C پیام هشدار می‌آید. (OCR در این نسخه نیست.)
* **سرریز متن**: اگر متن انگلیسی یک صفحه بسیار بلند باشد، ممکن است صفحهٔ B به دو
  صفحه کشیده شود؛ در این حالت صفحهٔ C همچنان با شکست صفحه شروع می‌شود و ترتیب
  A→B→C حفظ می‌ماند (فقط B دو صفحه‌ای می‌شود).
* **کلید API**: سرویس ISMC فقط کلیدهای با پیشوند `sk-` را می‌پذیرد و هدر لازم
  `x-litellm-api-key` است. کلید معتبر را از `https://ai.ismc.ir/ui` (بخش Keys) بسازید.
* **تاب‌آوری خطا**: اگر ترجمهٔ یک صفحه خطا بدهد، آن صفحه **ثبت نمی‌شود** و در اجرای
  بعدی به‌طور خودکار تکرار می‌گردد. صفحات سالم دست‌نخورده می‌مانند.
* **توقف تمیز**: با Ctrl+C (یا دکمهٔ توقف) بلافاصله پس از صفحهٔ جاری متوقف می‌شود و
  همه‌چیز ذخیره می‌گردد.

## ۶) معماری

```
pdf_translate.py
├── State          → دفترچهٔ وضعیت اتمیک (JSON)
├── Translator     → تماس با Chat Completions، بخش‌بندی متن، تلاش مجدد
├── render_page    → PyMuPDF → PNG
├── extract_text   → PyMuPDF → متن پاک‌سازی‌شده
├── build_docx     → ساخت Word (A/B/C) + تبدیل اختیاری به PDF
└── run()          → هستهٔ حلقهٔ صفحه‌به‌صفحه با قابلیت ادامه

app.py             → رابط وب محلی (http.server) روی run()
```
